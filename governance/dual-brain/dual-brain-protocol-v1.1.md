# 双脑协同机制 v1.1（定稿）

建立：2026-10-02　主脑：本机智妍（ClawWorkspace 工作区）　副脑：VPS hermes-agent（38.14.254.100）
权威来源：本文件 + 本地 `~/.workbuddy/MEMORY.md` 索引。VPS 侧 MEMORY 仅存角色标记副本，不演化独立规则。
验证：本机制草案已通过真实「门下省审议」复核（hermes 以审议角色返回有效意见，链路连通），并按意见修订至 v1.1。

---

## 0. 一句话定位

VPS hermes-agent = 我的**第二个大脑 / 门下省审议节点**。复杂任务先经「中枢院起草 → 门下省（副脑）审议 → 主脑定稿」，再执行与汇报。用户原话的口径是**「思考问题时互相复核后再汇报」**，故默认走模式 A。

---

## 1. 触发条件

- **启用双脑复核**：多步骤 / 高风险 / 长任务 / 用户明确要求「复核 · 三省六部 · 双脑」时。
- **L1 直通**：单文件小改、只读查询、普通问答、纯情感交流 → 不启用，直接做。
- 本机 `WorkBuddy` 的 Agent 模式（写文件/执行命令）下，凡涉及 L2/L3 动作必走审议。

## 2. 两种模式（解决「先执行还是先复核」的顺序矛盾）

草案 v1 把"主脑执行"和"副脑审议"混在一起，被副脑指出实为事后稽核而非门下省审议。定稿拆为两种：

**模式 A — 思考 / 方案复核（默认，对应用户原意）**
> 中枢院起草方案 → 副脑门下省审议 → 主脑定稿 →（尚书局执行）→ 礼部汇报
> 适用：规划、选型、分析、写作、给用户的方案类回答。

**模式 B — 执行前审批（实操类 L2/L3）**
> 中书省出变更单（范围/风险/回滚）→ 门下省审议（可暂缓）→ 尚书省执行 → 刑部验收
> 适用：改配置、部署、删改数据、外发、跨机写入等真实动作。

两种模式可串接：A 产出方案 → 执行阶段转 B。

## 3. 三省六部分工映射

| 机关 | 由谁承担 | 职责 |
|---|---|---|
| 中书省 / 中枢院 | 主脑 | 意图→任务包（目标/范围/风险/验收）；风险分级；变更单 |
| 门下省 / 审议角色 | **副脑（VPS hermes）** | 真实性/完整性/必要性审核；找遗漏·矛盾·隐患；给修正意见；L3 可暂缓 |
| 尚书省 / 执行角色 | 主脑 | 工具执行、调度、返回可验证结果 |
| 吏部 | 主脑 | 任务编号、优先级、SLA、owner、done 定义 |
| 户部 | 主脑 | 时间预算、依赖、凭据、端口、环境、同步窗口 |
| 礼部 | 主脑 | 进度回执、低噪声温柔汇报、**发送前脱敏复核** |
| 兵部 | 主脑 | 阻塞/压缩/回滚/失败升级 |
| 刑部 | 主脑（副脑可协审） | 验收标准、证据链、测试/日志/状态检查 |

## 4. 风险分级 L3 目录（命中即 L3，需用户二次确认）

- 删除 / 覆盖 / 迁移重要数据
- 修改 SSH、sudo、网络、防火墙、系统服务
- 写入 / 修改凭据、密钥、权限、访问控制
- 对外发送消息、发布内容、部署服务
- Git push、生产环境变更、域名 / DNS / 证书操作
- 付款、订阅、法律或合规相关操作
- 修改 MEMORY、SOUL、技能、自动化规则等长期行为配置
- 跨机器写入（VPS ↔ 本机同步）
- 任何不可逆或回滚成本较高的操作
> 注意：单文件改动若触及上述类别（如 SSH 配置、cron、权限文件、SOUL），不因其"单文件"而降为 L1。

## 5. 数据分级与脱敏（礼部负责发送前复核）

- **D0** 公开信息：可直接复核
- **D1** 非敏感工作上下文：可抽象后发送
- **D2** 内部路径 / 服务器 IP / 项目细节：最小化 + 脱敏
- **D3（禁出站）**：密码、私钥、token、Cookie、验证码、完整日志中的认证头
> 副脑审议 payload 不得含 D3；命令输出、异常堆栈可能藏隐性凭据，不靠人工扫一眼；不把用户原话、全量历史、完整 MEMORY 无差别转给副脑；复核结果也不得回显敏感信息。

## 6. 副脑权威等级与权限边界

- **权威等级**：L1 不启用；L2 副脑意见为强建议（主脑可记理由后采纳/驳回）；L3 副脑发现未解决的安全/权限/不可逆风险时，拥有**暂缓权**，需用户明确确认方可继续。
- **权限边界（硬约束）**：副脑仅有**审议权**。无自动执行权、发布权、删除权、审批权。可提建议或暂缓意见，但**不得替主脑落地任何动作**。

## 7. 执行前后两阶段

- **preflight（执行前）**：目标明确？范围锁定？回滚点？备份？资源预算？必要授权？—— 六确认齐了才动。
- **验收（执行后）**：达验收标准？外部状态检查？无副作用？实际变更记录？状态/风险结论更新？—— 对外发送/部署/git push/跨机写入尤须读回实测，不止信工具返回成功。

## 8. 异常分类与重试

区分：网络不可达 / SSH 认证失败 / hermes 进程启动失败 / 模型额度耗尽 / 副脑空响应 / 输出与任务无关 / 含危险命令 / 响应被截断 / 主副结论冲突。
- 每类错误设最大重试次数；允许换模型或缩短 payload。
- 空响应、异常响应、部分响应**不得标记为"已复核"**。
- 触发安全红线或持续失败时**停止而非继续降级**。

## 9. 降级策略

hermes 240s 无响应或网络超时（已知 VPS 访问海外接口不稳）→ 主脑按三省六部本地代审，汇报中标注「副脑复核缺失，已本地代审」，不阻塞用户。

## 10. 审计记录

每次双脑任务记：`task_id` / 摘要 / 风险级 / payload 数据级 / 主方案版本 / 副脑状态 / 意见摘要 / 最终决策 / 执行结果 / 回滚点 / 是否降级 / 用户批准。
> 审计记工作区日志或专门审计文件，**不把原始 prompt/完整输出长期塞进 MEMORY**（MEMORY 记机制不记流水账）。

## 11. 调用协议

```
ssh taoque-vps                      # 已配 ed25519 密钥，免密
hermes -z "<门下省审议 prompt>" chat --cli
```
- prompt 须要求：以门下省角色、按三省六部复核、只审议不执行、输出 1)遗漏 2)矛盾/隐患 3)修正意见。
- payload 脱敏，不注入 D3。
- 单次审议 timeout 300s；超时按 §9/§10 处理。

## 12. 版本 / 冲突 / 撤销

- 机制带版本号（当前 v1.1）。
- 主脑侧（MEMORY + 本文件）为唯一权威；主副配置不一致以主脑为准。
- 撤销：删 MEMORY 小节 + 移除 VPS 标记即失效。
- 副脑标记变更须由主脑侧发起，不得 VPS 侧自行演化规则。
