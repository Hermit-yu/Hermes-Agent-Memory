# EDICT 日常应用手册（实操版）

## 1. 日常如何用

### 聊天请求（普通问答/轻量修改）
- 先由中书省识别操作类型。
- `L1`（如单文件小改、只读查询）可直通执行。
- 执行后补一条审计记录（谁、做了什么、结果）。

### 任务执行（批量改动/跨目录变更）
- 先跑 preflight。
- 命中 `L2`（如批量编辑）必须拿到 `APPROVED` token。
- 尚书省调度执行，兵部落地，失败即回滚。

### 上线变更（高影响动作）
- `L3` 默认双人审批（门下省 + 刑部/工部）。
- 执行前必须有回滚点；执行后必须审计复核。

### 定时任务（cron）
- 视为高风险变更，默认 `L3`。
- 必须双签 + 回滚方案 + 生效后观察窗口。

## 2. 何时必须审批，何时可直通
- **直通**：L1 且不涉及外发、权限提升、定时策略改动。
- **必须审批**：
  - L2：批量文件改动、跨模块执行。
  - L3：外发消息、cron 变更、高影响配置变更。
- **必须双签**：所有 L3。

## 3. 如何减少打断感（分级审批 + 快速通道）
- 对 L1 开启“默认直通+事后审计”，减少等待。
- 对 L2 提供“标准模板审批”，仅确认风险点，不重复描述。
- 对 L3 建立“快速双签通道”：
  1) 先给一页摘要（目标/影响/回滚）
  2) 一次性会签
  3) 自动生成审计条目
- 对重复低风险操作建立白名单（仍留审计）。

## 4. 每日/每周复盘（可量化）

### 每日（10 分钟）
- 看三项：
  - 审批时延（P50/P90）
  - 驳回率（rejected / total）
  - 误放行率（事后认定应拒绝但放行）
- 输出当日改进动作（最多 3 条）。

### 每周（30-45 分钟）
- 汇总 L2/L3 案例，抽样复核。
- 更新审批矩阵和 runbook 的薄弱点。
- 形成下周治理目标：降低时延、降低误放行、提高一次通过率。

## 5. 推荐落地节奏
1. 先上线 preflight + audit-log（当天可用）。
2. 一周内固化审批矩阵（操作→风险→审批链）。
3. 两周内形成复盘机制并纳入周例会。
