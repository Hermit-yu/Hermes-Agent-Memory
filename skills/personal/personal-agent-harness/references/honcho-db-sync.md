# Honcho DB sync reference

Used by `personal-agent-harness` import procedure (step 10) and verification after service restart.
DB connection: localhost:5432, user postgres, db postgres, pw postgres. Messages table columns: public_id, content, metadata, peer_name, workspace_name, session_name, token_count. Constraint ck_messages_public_id_length requires length(public_id) = 21 exactly — verify with python3 before INSERT (arbitrary lengths fail silently or CHECK violation). Insert: SELECT with 21-char public_id, content = file path + version + purpose, now(), workspace hermes. Sync: recallSync=true (verify via grep); per-directory session strategy; default load requires profile/toolset reference. DB clear: ONLY user-requested pre-transfer cleanup, never automatic. Service check: honcho status (api/deriver/db/redis healthy); docs returns 200; /v3/workspaces/{id}/search and /conclusions/query need auth/filter params. If honcho_search fails with initializing: check pgrep -f honcho; restart with LLM_*_API_KEY set.
