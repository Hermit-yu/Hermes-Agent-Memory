# 交互式前端交付（Interactive Frontend Delivery）

适用场景：重建或修复云平台 / 安全面板的前端，用户要求"完整可用的功能和界面"而非仅展示卡片说明。

## 核心规则（Always-On）

- 描述内容 ≠ 实际功能。每个功能视图（Assets/Findings/Investigate/AiView/Plans/Audit/Monitor/Settings）必须包含真实数据绑定调用（`fetch()` 或等效），并渲染到 DOM（`v-for`、列表、表格），而非仅静态文本占位符。
- 前端修复黑屏时：直接写入内容到 `App.vue` + 对应视图文件，重建同步，不要依赖路由骨架为空渲染。
- 交付前必须执行：`npm run build` → `deploy/sync-site.sh` → `curl -k --max-time 3` 验证内容真实可见（不是构建成功即止）。
- 用户风格：直接简洁中文回复，不填充"好的，我来"、"正在处理"等无信息文本；每次工具执行后给最终回执（做了什么/什么命令/什么效果 + 验证证据）。
- 用户界面文字 = 大白话（用户两轮明令纠正）：页面上不出现英文状态码（success/pending/open/…）、原始 JSON、§条款号、内部字段名。状态/事件/动作/角色值一律翻译；翻译集中放在一个 labels.js 式字典里，所有视图 import 同一字典，禁止各页现写散落的映射。
- 解释性"术语卡片"（哪吒式 jargon 堆砌面板）是删掉的对象，不保留：换成一句话大白话说明即可。
- 当用户说"继续修刚才的bug"或中断时，不重复已做内容描述，直接执行修复并报告真实状态变化，避免重复解释已完成步骤。

## 步骤顺序（Procedure）

1. **确认视图缺失状态**：检查 `/workspace/` 或项目 `src/views/` 下每个功能视图文件是否存在内容（非空白/骨架）。
2. **写真实交互内容**：每个视图文件写入 `<template>` 包含 `fetch()` 调用（指向实际后端 `/api/*` 端点）+ 数据渲染（`v-for` 或等效循环）。文案全中文大白话，解释用一句话直说，不堆术语卡。
3. **修黑屏**：`App.vue` 直接写入内容（标题 + 卡片 + 运行状态区），不依赖空路由渲染。
4. **构建验证**：运行构建命令（如 `npm run build`），确认无构建错误（检查控制台输出最后 3 行，非"exit 0"即失败）。
5. **同步部署**：执行同步脚本（如 `deploy/sync-site.sh`），确认同步成功（检查 `nginx reload` + `php-fpm USR2` 输出，非成功即失败）。
6. **真实内容验证**：`curl -k --max-time 3 https://yuntong.taoque.top/` 或对应站点 URL，`grep` 确认内容关键词（功能名/数据表/状态区）出现在响应中（构建后内容由 JS 渲染，需检查构建产物大小变化 + 浏览器刷新验证，非仅检查 HTML 源码）。
7. **后端确认**：确认后端健康（`curl /api/health` 200；本项目 PHP-FPM 走容器，健康检查从宿主 curl 即可），DB 表存在并可查询（`docker exec mysql …` 或等效）。
8. **交付报告**：直接列出已完成模块（如 Assets/Findings 已接入真实 API 数据绑定，其余视图内容已填充），并明确指出仍缺的具体交互（如"添加资产表单提交"、"查看证据按钮"），不泛泛说"已修复"而不说明缺什么。

## 关键陷阱（Pitfalls）

- **陷阱：只填描述卡片而不接数据**。修复方法：每个视图文件必须包含可运行的 `fetch()` 调用和数据渲染循环；构建完成后必须检查构建产物（如 `dist/assets/index-*.js` 大小变化）并用浏览器刷新验证内容可见。
- **陷阱：构建成功 ≠ 内容同步成功**。修复方法：`sync-site.sh` 可能因目录缺失或 nginx 配置错误失败；每次同步后检查 `nginx -t` 和站点可访问状态。
- **陷阱：用户中断（"继续修刚才的bug"）时重复解释已完成内容**。修复方法：中断后直接执行修复动作（写文件/构建/验证），报告结果变化，不重复历史步骤。
- **陷阱：用静态 HTML 说明替代真实交互模块**。修复方法：实际功能模块必须有可执行的数据绑定代码（非注释中的"已实现"），并可通过实际 API 调用验证。
- **陷阱：忽略缓存**。修复方法：浏览器缓存可能使修改内容不可见；验证时使用 `Ctrl+F5` 强制刷新或在请求中加缓存破坏参数（如 `?vN`）。
- **陷阱：翻译字典键名凭记忆写**。修复方法：写 labels 前先查两个真源——后端白名单（如 collector.php 的 probe 键）与数据库实际值（`SELECT DISTINCT status/event_type/evidence_type …`）；键不匹配时 `t()` 兜底原样返回，改起来要全站返工。
- **陷阱：透传列直接渲染后端 JSON/复合标识符**。修复方法：详情/目标列加显示层翻译（JSON.parse → 逐键翻成短语，布尔值丢弃，解析失败截断展示原文；标识符如 `plan#6`、`cron-host-YYYYMMDDHHMMSS` 用正则解析成"处置建议 #6""定时检查 · host · 日期"）。不动数据库，只改展示层。
- **陷阱：shell 嵌入变量拼 JSON 断言必翻车**。在 `curl -d '{"time_from":"$(date ...)"}'` 这类行内 heredoc/单行命令里，shell 先展开变量导致 JSON 值带不可见空格/换行、甚至整个 payload 被拆断（表现为端点返回 id=0 或 400 而非预期）。规则：E2E 脚本里日期/变量一律先 `VAR=$(...)` 单独赋值，再以 `"$VAR"` 拼 JSON；或把整段写成 .sh 文件再执行（同用户大块命令规则）。
- **陷阱：断言"按钮/区块不存在"前先查数据门控**。多数列表页的默认选中项来自"最后一台资产"之类规则，若该资产没有数据（0 发现/0 计划），v-if 门控的按钮根本不会渲染——不是 UI 缺失。验收前先确认被选资产有数据，没有就切到/造出有数据的资产再断言；API 侧同构（先 GET 列表看分布再点按钮）。
- **陷阱：curl 测会话型 API 拿不到 cookie**。修复方法：PHP 会话的 sid 在 `Set-Cookie` 头而非 JSON 响应体里；用 `curl -c jar.txt` 登录再从 jar 里取 sid 作后续请求的 `-b`，别从响应 body grep。注意登录请求本身也要先看原始返回判成败（`{"ok":true,"id":N}` 才有效），id=0/null 说明 payload 没成形，后续全 404 是连锁假象。
- **陷阱：全站改文案后只 curl 验收**。修复方法：浏览器逐页点一遍，用正则扫 `document.body.innerText` 找英文状态码残留再宣称完成；正则必须用非捕获组 `(?:…)`，否则捕获组会产出空串误报。
