# 多代理长任务进度与交接配方

配套 SKILL.md「多代理编排运行模式」。适用于：主编审 + 编码子代理 + 独立复核子代理协作的长编码任务，且用户要求随时看进度 / 定期汇报 / 防偷懒。

## 1. 里程碑看板文件（如 `docs/进度看板.md`）

- 顶部：状态四态分开标注——**已实现 / 已测试 / 已部署 / 真实服务器验证**，四者不可互相冒充（大纲 §10 明令）。
- 里程碑表：一行一个 M0…Mn，列「内容 / 状态 / 证据·回滚点」。
- 「当前里程碑实况」区块，每轮更新：产出清单、子代理自述验证项、主编审现场挑出的疑点、复核子代理 id 与总判定。
- 每次里程碑推进或用户要「复核全盘进度」时刷新。

## 2. 只读进度探子脚本（如 `progress.sh`）

- 只读、不改动任何东西。输出：`git log --oneline -5` + `git status --short` + 新产物文件清单 + 看板关键行 + 各子代理 live 日志路径。
- 用途：主编审和定时任务都从它取数，避免每次手敲、也避免凭记忆报进度。
- 跑它前先 `cd` 到项目目录或用 `workdir`（工作目录残留到已删路径会让后续命令 126，见 terminal cwd 坑）。

## 3. 定时自动汇报（cron）

- 周期：用户指定为准；未指定默认 15 分钟。workdir 锚到项目目录。
- 数据源：看板 + `git log/status` + 各子代理 live 日志尾 + 探子脚本。全部真实读取，禁止编造。
- 汇报行格式（简洁、Telegram 友好）：
  - ◆ 里程碑：<当前卡点一行>
  - ◆ 编码代理A：<running N 分钟 或 已完成>；最近动作 2–3 条
  - ◆ 复核代理B：<待命 / 进行中 + 最近动作>
  - ◆ 主编审：<本轮核了什么 / 签了什么 / 催了什么>
  - ◆ 新完成细项（比上次多的）：逐条，没有写「无」
  - ◆ 卡点 / 风险：一句话，没有写「无」
- 某代理日志停滞 > 20 分钟或报错 → 单独标红提醒。汇报只报事实，读不到的写「未见」。
- 收尾时（任务结束 / 用户说停）记得 remove 该 cron，别让它继续空报。

## 4. 子代理交活时，主编审必跑的交接核对清单

1. `git log` 有没有**独立** commit（子代理说「已提交」常指基线 commit，交付点根本没成型）——没有独立 commit，回滚点不成立，打回。
2. live 探活：`curl` 目标端点读真实 HTTP 码；子代理自述的 200/失败必须现场复现，复现不一致就按现场为准。
3. 逐条比对子代理「已验证」列表 vs 自己读到的事实，对不上一律打回，不沿用其数字。
4. 全绿才交给复核子代理；复核子代理是干净上下文独立挑错（6 维矩阵 + 红线），主编审不审自己、也不代复核签。
5. 复核出的阻断项 → 派编码子代理修 → 复验 → 主编审汇总签核 → 才进下一里程碑。

## 5. 通用坑（WHY 各附一句）

- 子代理起的本地服务常是临时态、跑完就退：「已 200」不代表驻留，交接必 curl 复现（WHY：临时起 nginx/fpm 验证完没重启进程，端口已空，200 变成 000）。
- 工作目录残留：删过某目录后 shell cwd 卡在被删路径，后续命令 126（WHY：getcwd 失败）——用 `workdir` 参数或先 `cd` 到有效目录再跑。
- 把基线 commit 当交付点：M0 审计落盘的那个 commit 只是回滚锚点，M1 代码必须另成 commit（WHY：否则「回滚到 M1 之前」没有独立 SHA 可指）。
