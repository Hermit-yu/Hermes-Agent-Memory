# SOURCE-OF-TRUTH.md — 智妍 Personal Agent 权威来源矩阵

> 状态：Active
> 生效：2026-10-02
> 权威仓库：`Hermit-yu/Hermes-Agent-Memory`
> 目的：明确每类长期信息的唯一主来源，防止 WorkBuddy、Hermes、本地记忆和历史副本各自演化。

---

## 1. 总原则

1. **Hermes-Agent-Memory 是治理、人格母本和项目规则的权威仓库。**
2. Hermes 与 WorkBuddy 可以持有运行时文件和缓存，但不得在本地发展一套与仓库冲突的长期规则。
3. 用户当前明确指令始终高于历史文件；涉及长期规则的变更，应先在权威仓库落盘，再同步到运行时。
4. 运行时事实（服务状态、当前任务、在线心跳）不能写成永久事实；必须带时间戳并由实时检查确认。
5. 一次性任务进度、Commit SHA、临时备份路径和短期错误不进入长期记忆。
6. 多处出现同一规则时，非权威位置只保留摘要和链接，不复制完整正文。
7. 密码、私钥、Token、Cookie、验证码等 D3 数据不得进入仓库。

## 3. 文件状态约定

权威文档建议在顶部使用以下状态：

- `Active`：当前生效，允许被运行时引用。
- `Draft`：候选方案，未获批准，不得自动执行。
- `Superseded`：已被新版本取代，仅供追溯。
- `Archived`：历史资料，不参与当前决策。

若文件没有状态：

- `governance/` 和正式项目目录中的最新明确版本，可结合变更历史判断；
- `reports/`、`deliveries/`、`archive/reports/`、`archive/tmp/` 默认不是权威来源；
- 无法确认时停止猜测，向用户确认或采用保守方案。

## 4. SOUL 双层结构

### 4.1 母本

`hermes-vps/SOUL.master.md`

保存完整的人格细节、生活侧写、表达素材、关系互动方式和演化历史。母本用于：

- 灾难恢复；
- 人格审计；
- 核心版重新生成；
- 跨智能体迁移；
- 用户审阅完整人设。

母本不需要每轮全部注入上下文。

### 4.2 核心运行版

`hermes-vps/SOUL.core.md`

只保存每轮都需要的：

- 身份与关系锚点；
- 真实、结果、安全、尊重原则；
- 核心说话方式；
- 情绪和模式边界；
- 工作协作底线；
- 记忆基本规则；
- 指向治理和任务 Skills 的入口。

Hermes 的 `/root/.hermes/SOUL.md` 应与该文件保持一致。

### 4.3 兼容文件

`hermes-vps/SOUL.md`

为兼容既有同步和恢复流程，现阶段保留为核心运行版镜像。完整母本永远使用明确文件名 `SOUL.master.md`，避免以后歧义。

## 5. 治理与项目规则边界

### 5.1 仓库负责定义

Hermes-Agent-Memory 负责保存：

- 治理原则和版本协议；
- 风险、数据、审批与审计规则；
- 双脑角色与仲裁；
- 项目模板和运行标准；
- 灾难恢复说明；
- 重要设计决定和演化历史。

### 5.2 Skill 负责执行

Hermes Skills 负责：

- 根据任务触发对应规则；
- 把仓库制度转化为可执行步骤；
- 调用工具、验证结果、处理异常；
- 在发现制度落后或错误时提出并同步修订。

Skill 不应复制整套治理正文，也不应在未经用户批准时改变角色、权限或长期安全边界。

### 5.3 MEMORY 负责稳定事实

MEMORY 只保存：

- 用户身份和稳定偏好；
- 关系与时间锚点；
- 双脑自适应切换的简短规则；
- 大任务一次授权等跨任务长期约定。

完整协议、项目状态和操作手册不放进 MEMORY。

## 6. 变更流程

长期规则变更采用以下顺序：

1. 用户提出或确认变更；
2. 确认应该修改哪一个权威来源；
3. 备份旧版本并创建小批次变更；
4. 检查冲突、敏感信息和引用关系；
5. 更新对应 Skill 或运行时镜像；
6. 验证运行时与权威文件一致；
7. 提交并同步 Hermes-Agent-Memory；
8. 报告变更、证据和回滚方式。

不得先在多个运行时文件分别修改，再事后猜测哪个版本正确。
