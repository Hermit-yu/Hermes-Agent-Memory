# Round 02｜指标半自动化与口径统一

## 1) 本轮目标
- 建立可运行的指标统计脚本，减少手工统计。
- 统一当前阶段统计口径，保证跨轮次可比性。
- 沉淀 Round 02 报告与总体索引，形成可追踪证据链。

## 2) 执行项
1. 新增脚本：`scripts/collect-round-metrics.ps1`
   - 参数：`-From`、`-To`、`-RoundId`（可选）
   - 输入：`memory-echoDB/indexes/edict-audit-log.jsonl`
   - 输出：
     - `reports/metrics/round-metrics-<RoundId>.json`
     - `reports/metrics/latest-round-metrics.json`
2. 更新 `METRICS.md`
   - 新增“统计口径定义”
   - 明确“估算口径”与“严格口径”升级路径
3. 同步项目汇总与 README 进度状态。

## 3) 可验证结果
- 验收命令：
  - `powershell -ExecutionPolicy Bypass -File projects/智妍的自我提升计划/scripts/collect-round-metrics.ps1 -RoundId R02`
- 文件落地：
  - `reports/metrics/round-metrics-R02.json`
  - `reports/metrics/latest-round-metrics.json`

## 5) 风险与问题
- 当前 preflight 相关识别采用启发式（`operation` 文本 + `decision` allow/deny），可能高估覆盖率。
- `roughPreflightCoverage` 在当前口径下可能 >1，说明“相关记录”与“高风险记录”非一一映射。
- 仍需推进结构化审计字段以支持严格口径。

## 6) 下一轮计划（Round 03 建议）
- 引入结构化 preflight 标记（如 `preflight=true` / `phase=preflight`）。
- 将完整率升级为 schema 校验通过率，并记录失败原因分布。
- 对统计窗口增加轮次 tag 维度，避免跨场景混算。
