# WORKFLOW EXAMPLES（审批与审计示例）

## 场景 1：高风险外发消息审批

### 触发
- 发送到外部渠道（Telegram/Discord/Email）且内容含业务敏感信息

### 流程
1. 中书省生成外发草案（目标、内容、影响）
2. 门下省审核：是否必要、是否可脱敏
3. 刑部复核：隐私与合规风险
4. 尚书省执行外发（仅在双签通过后）
5. 记录审计日志与消息 ID

### 审计重点
- 审批人、审批理由、目标渠道、最终发送内容哈希

---

## 场景 2：工作区批量改动审批

### 触发
- 单次改动 >= 10 文件，或涉及核心结构文件（如 README、结构说明、自动化脚本）

### 流程
1. 中书省提交变更单：范围、风险、回滚方案
2. 门下省审核：是否拆批、是否影响主链
3. 尚书省授权兵部执行改动
4. 执行后输出变更清单 + git diff 摘要
5. 刑部抽检审计（随机或高风险必检）

### 审计重点
- 变更前后文件清单、回滚点（commit hash）、是否越权改动

---

## 场景 3：定时任务（cron）变更审批与审计

### 触发
- 新增/修改/删除定时任务（频率、执行命令、目标环境）

### 流程
1. 中书省给出变更申请（目的、窗口、失败影响）
2. 门下省审核合理性与时间窗
3. 刑部审核命令安全性（避免危险参数）
4. 尚书省执行变更并做一次 dry-run
5. 记录执行结果、下次触发时间、告警配置

### 审计重点
- cron 表达式、执行命令版本、审批链、dry-run 结果、回滚指令

---

## 最小执行原则

- 无审批不得执行高风险动作
- 审批不替代执行验证：所有批准后动作仍需记录结果
- 紧急放行必须 24h 内补审计
