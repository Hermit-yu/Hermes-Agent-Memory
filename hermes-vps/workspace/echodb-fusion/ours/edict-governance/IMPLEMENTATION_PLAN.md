# IMPLEMENTATION PLAN（edict-governance）

## Phase 1：治理骨架落地（可立即）

### 输入
- 上游 edict 快照（README / LICENSE / 文件清单）
- 当前 OpenClaw 工具能力与风险分级

### 执行清单
1. 定义高风险动作清单：`message.send`、批量 `edit/write`、`exec` 涉及系统变更、cron 变更
2. 建立审批数据结构（见 `POLICY_TEMPLATE.json`）
3. 为三类场景写标准流程（见 `WORKFLOW_EXAMPLES.md`）
4. 输出审计最小字段：who/what/why/approve/log/ref

### 输出
- 可执行策略模板 v0.1
- 场景化审批流程文档
- 融合记录（风险与边界）

### 验收
- 能区分“需审批/无需审批”
- 每次高风险动作有审批记录
- 审计日志可追溯到执行命令与文件改动

---

## Phase 2：制度强化（中期）

### 输入
- Phase 1 审批日志样本
- 误拦截/漏拦截统计

### 执行清单
1. 引入双人审批（特定级别）
2. 增加配额与时间窗（如夜间外发限制）
3. 审批理由结构化（风险标签、影响范围）
4. 日报汇总：批准率、驳回率、高风险分布

### 输出
- 策略模板 v0.2（含双签与时窗）
- 每日治理报表模板

### 验收
- 关键场景误放行率下降
- 审批效率可量化（平均审批时延）
- 运营侧可复盘驳回原因

---

## Phase 3：工程化闭环（中长期）

### 输入
- 稳定策略模板
- 历史审计与回滚案例

### 执行清单
1. 审批与执行联动（未批准不可执行）
2. 回滚标准化（文件、配置、任务）
3. 例外机制（紧急放行 + 事后审计）
4. 与监控系统联动（异常即时告警）

### 输出
- 治理执行闭环（审批→执行→审计→回滚）
- 版本化策略管理

### 验收
- 高风险动作 100% 可追溯
- 关键变更具备可验证回滚路径
- 治理规则升级不影响主链稳定
