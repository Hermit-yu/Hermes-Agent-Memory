# R04 交付件｜结构化字段接入方案（v1）

## 1. 背景与目标
当前 strict 口径依赖 `operation` 文本匹配，导致：
- preflight 证据可解释性弱；
- 日志异构时交集统计不稳定；
- 周报验收口径可读性不足。

本方案目标：在不破坏现有日志兼容性的前提下，引入最小结构化字段集合，支撑 strict 指标稳定落地。

## 2. 字段设计（最小集）
在审计记录中新增以下字段（可选→逐步必填）：

- `event_type`：事件类型
  - 枚举建议：`preflight` / `execute` / `rollback` / `audit_only`
- `phase`：流程阶段
  - 枚举建议：`before_action` / `decision` / `after_action`
- `preflight_flag`：是否属于 preflight 证据
  - 布尔：`true/false`
- `op_key`：操作归一化键（用于去重交集）
  - 建议：稳定字符串（如 `gateway.restart`、`fs.write:/projects/...`）

兼容策略：旧字段 `operation` 继续保留，`op_key` 缺失时回退到 `operation`。

## 3. 口径升级规则（strict v2）
- `uniqueHighRiskOps`：L3 且 `event_type=execute` 的 `op_key` 去重集合；
- `uniquePreflightOps`：`preflight_flag=true` 且 `event_type=preflight` 的 `op_key` 去重集合；
- `strictIntersectOps`：两集合交集；
- `strictPreflightCoverage = |strictIntersectOps| / |uniqueHighRiskOps|`。

> 迁移期允许“结构化优先、文本回退”：
> 若 `op_key/event_type/preflight_flag` 缺失，则按旧规则回退，并在报告标记 `compat_fallback=true`。

## 4. 接入步骤（稳态优先）
1. **S1（本周）**：在写审计日志处透传新字段（可空），不改现有消费逻辑。
2. **S2（本周）**：`collect-round-metrics.ps1` 增加“结构化优先 + 回退模式”读取分支。
3. **S3（下周）**：周报新增 `compat_fallback_ratio`（回退比例）。
4. **S4（下周）**：当回退比例 <5% 时，切 strict 纯结构化口径并冻结旧回退。

## 5. 验收标准
- 指标结果可重复：同一窗口重复跑差异为 0；
- strict 输出始终在 `[0,1]` 或 `N/A`；
- 报告可解释：可追溯到 `op_key` 交集样本；
- 迁移安全：旧日志不报错，且有 `compat_fallback` 标记。

## 6. 风险与解法
- 风险：上游未及时补 `op_key`。
  - 解法：回退 `operation` + 周报跟踪回退比例，逐步压降。
- 风险：`event_type` 枚举漂移。
  - 解法：在脚本中加入白名单与 unknown 计数。
- 风险：布尔字段缺失导致漏算。
  - 解法：`preflight_flag` 缺失时仅用于 rough，不进入 strict 主集合。
