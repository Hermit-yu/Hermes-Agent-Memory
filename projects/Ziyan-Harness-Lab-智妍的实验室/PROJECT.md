# Ziyan Harness Lab - 智妍的实验室

> 状态：Backlog / 待正式立项
> 类型：长期大项目
> 创建：2026-10-02
> 当前阶段：仅登记，不启动开发、不分派 Worker、不创建生产资源
> 发起人：桃雀
> 执行主体：智妍；WorkBuddy 在线时参与主脑决策与审议

---

## 一句话定位

建立一套用于验证个人智能体人格一致性、安全边界、任务规划、工具执行、双脑协作、真实验收和升级回归的实验与评测平台。

它不是新的笔记软件、知识库或项目管理器，而是现有 Personal Agent Harness 的质量验证系统。

---

## 项目目标

1. 把现有 SOUL、MEMORY、Skills、三省六部、双脑协议和任务授权规则转化为可重复运行的测试场景。
2. 在 Hermes、WorkBuddy、模型、Provider、核心人格或 Skill 更新后，自动发现行为退化。
3. 验证智能体是否真的执行了 Preflight、风险判断、工具调用、进度回执、结果验收和数据脱敏。
4. 区分“输出看起来正确”和“实际行为符合要求”。
5. 为未来扩大真实项目权限提供可审计的安全依据。

---

## 首版 MVP 范围

首版仅做可运行的测试核心，不先建设大型管理平台：

- YAML/JSON 场景定义；
- 场景 Schema 校验；
- Hermes 单智能体运行适配器；
- 临时目录、Git Worktree 或 Docker 隔离执行；
- 自动规则判定与人工复核入口；
- Markdown/HTML 测试报告；
- GitHub Actions 回归入口；
- Telegram 测试结果通知；
- 10个核心回归场景。

首版不包含：

- 自动修改 SOUL、MEMORY 或 Skills；
- 在生产服务器执行破坏性测试；
- 自动授予更高权限；
- 大型可视化平台；
- 对所有模型和 Agent 框架的通用兼容。

---

## 首批核心场景

1. 身份、称呼与基本语气一致性；
2. 不确定信息不得伪装成确定结论；
3. 可执行任务必须真实调用工具；
4. 长任务必须提供里程碑或阻塞回执；
5. 一个大任务的普通命令只确认一次；
6. L3 高风险动作必须单独二次确认；
7. D3 敏感信息必须脱敏并禁止出站；
8. 工具返回成功但真实结果失败时，不得声明完成；
9. WorkBuddy 离线时智妍自动接管主脑职责；
10. 最终完成状态必须附带可复核证据。

---

## 预期验证维度

- 人格一致性；
- 事实准确与不确定性表达；
- 任务规划与 Definition of Done；
- Preflight 与范围控制；
- 工具执行真实性；
- 任务级授权；
- L1/L2/L3 风险识别；
- D0–D3 数据处理；
- WorkBuddy / 智妍双脑路由；
- 进度可见性；
- 验收证据完整性；
- 回滚与失败处理；
- 记忆和 Skill 的正确沉淀；
- 版本升级后的行为回归。

## 正式开工触发条件

只有用户明确说“启动 Ziyan Harness Lab / 智妍的实验室”或等价指令后，才进入立项和执行。

正式开工前必须：

1. 明确首版 Definition of Done；
2. 选择仓库位置和许可证；
3. 完成技术 Spike；
4. 定义测试所需模型、Provider 和成本上限；
5. 建立不会触碰真实生产数据的隔离环境；
6. 对测试夹具进行 D3 扫描；
7. 确认 WorkBuddy 是否参与首轮双脑审议；
8. 获得该大任务的一次总授权。

---

## 成功标准

MVP 至少满足：

- 10个核心场景可以重复运行；
- 测试结果可区分自动通过、自动失败和需要人工复核；
- 不使用真实秘密作为测试夹具；
- 一个已知错误可以被测试稳定捕获；
- 修改核心 SOUL 或 Skill 后能够运行回归并展示差异；
- 报告提供输入版本、环境、结果、失败原因和证据；
- 所有测试副作用被限制在隔离环境；
- 项目自身具备测试、备份、恢复和运行说明。
