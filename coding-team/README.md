## 新成员入职步进页

### 入职流程概览

1. **加入团队 Slack/钉钉**  
   - 加入团队官方沟通渠道  
   - 读取团队行为准则  

2. **获取访问权限**  
   - 通过 Git 权限管理系统获取团队代码仓库访问权限  
   - 获取内部工具（CI/CD、监控、文档等）访问权限  

3. **完成团队文化培训**  
   - 观看团队文化介绍视频  
   - 了解团队价值观与工作方式  

4. **完成技术栈培训**  
   - 熟悉主要技术栈（语言、框架、工具）  
   - 阅读技术文档，完成基础操作练习  

5. **完成代码审查与合作流程培训**  
   - 学习 PR 流程、代码规范、审查要求  
   - 熟悉代码托管平台（GitHub/GitLab）操作  

6. **完成安全与合规培训**  
   - 阅读安全指南，完成安全培训  
   - 确认密钥管理、权限最小化等安全规范  

7. **完成团队介绍与角色确认**  
   - 参加团队成员介绍会  
   - 明确个人角色与职责范围  

8. **完成初步任务**  
   - 在代码仓库中提交第一个 PR（修复 typo 或小功能）  
   - 获得审查通过，完成初步交付  

### 入职验收标准

- 成功获取所有必需访问权限  
- 完成所有必需培训并通过相关测试  
- 提交第一个可审查的 PR 并获批  
- 在团队沟通渠道中活跃参与  
- 完成团队文化与行为准则确认  

### 备注

- 所有入职步骤均需在首月内完成  
- 如有特殊情况（如海外人员、特殊岗位），需在入职前与 HR 协调特殊安排  
- 入职文档请同步更新到 team README 中，保持最新状态

## 协作流程（Kanban 驱动）

采用官方「工程流水线」模式（分解 → 并行 worktree 实现 → 审查 → 迭代 → PR）：

1. **需求进来** → 朴智妍（CTO）建母任务卡，指派含恩静做设计
2. **设计产出** → 含恩静把技术方案写进 `docs/`，关键决策写进 `decisions/`，并把接口契约写进子任务卡正文（并行 worker 看不到兄弟卡片，决策必须随卡走）
3. **实现** → 朴智妍 `kanban_create` 扇出编码卡（`--workspace worktree`）给朴素妍，各卡独立 worktree 分支
4. **测试** → 编码卡完成触发朴孝敏的测试卡（`--parent` 链接继承父卡交接）
5. **审查** → 朴孝敏过质量门 / 李居丽过安全性能门 / 用 `kanban_request_review`
6. **交付** → 全宝蓝走 `ops/` 发布，留回滚点
7. **收尾** → 完成摘要与 metadata 存档到 `reports/`，原始卡进 `archive/`

## 约束（全员遵守）

- 每个编码任务在独立 worktree 分支内做，不直接改主分支
- 完成任务必须调用 `kanban_complete(summary, metadata)`，留足交接证据（改了什么 / 怎么验证 / 还剩什么风险）
- 分支冲突不自行裁决 → 建中立调解卡，双方卡都 `--parent` 链入
- 同一文件反复冲突 → 留 `hotspot: <file>` 评论，编排器为该文件单开重构卡
- 密钥/凭据/敏感日志不进任务正文与 metadata，只存指针
- 任务卡正文必须携带该卡依赖的全部决策，因为 worker 看不到兄弟卡片
